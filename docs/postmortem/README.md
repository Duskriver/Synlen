# 事故复盘

事故写实：一个 bug 到达了它不该到达的地方（真实用户、合并的 PR、发布版本），有意思的部分是**我们的流程为什么放它过去**，而不只是一行修复。

复盘不是 [Agent Note](../../.agents/notes/README.md)——后者记录深思熟虑的设计决策与被否决的备选。复盘是面向过去的失败记录：坏了什么、机制是什么、每道安全网为什么没拦住、加了什么护栏让同一类缺陷下次响亮地失败。

什么时候写：**微妙**（机制不显然，认真的工程师会重新辛苦推导一遍）、**系统性**（漏过的原因是测试 / 工具 / 约定的缺口，不是一次性笔误）、**重新发现代价高**（花过真实调试时间，还会再花一次）。链接它促成的护栏（测试、[常驻指令](../../AGENTS.md)、Agent Note）。

每篇复盘以**执行摘要**开头：一段 30 秒能读完的话——坏了什么、根因的平实说法、为什么漏过、持久的教训——然后是 Summary / Timeline / Root cause / Guardrails 小节。
