# Agent Note: 词卡反馈与直连发音

Status: implemented

## Problem

词卡与正文颜色接近，打开后缺少明确的选词标记和触觉反馈；卡片随内容增长改变高度，阅读位置容易被生成过程打断。单词发音先查询词典条目再下载音频，任一请求迟迟不完成都会拖延阿里云 TTS 回退，点词后长时间无法朗读。

## Decision

词卡采用与安全视口成比例的固定高度，将长内容留在内部滚动区域，避免流式文本和标签切换改变浮层边界。阴影、描边与轻量遮罩共同区分卡片和正文；具体尺寸与交互契约由 [learning 模块参考](../../../../docs/subsystems/learning.md#边界与不变量)持有。

原词标记使用 DOM 提供、经原生视口与宿主转换的各可见词片段，绘制在同一个 Flutter 路由中；包围框仅定位词卡。软连字符可让同一个词跨行，直接填充包围框会误染两行间的邻词，逐片段着色保留实际文字范围。标记随词卡一起消失，不需要给 Readium 正文增加另一套选区或修改 DOM。触觉反馈由入口的实际打开、关闭动作触发，重复调用不叠加反馈。

单词音频直接从有道取得完整美音 MP3，请求和下载共用短时限；服务返回可用字节后才交给播放与缓存。完整下载放在回退判断之前，使响应正文停滞也能切换到 TTS。取消仍终止本次学习，不把取消当作发音失败。对外发送范围由[隐私说明](../../../../docs/user/privacy.md#离开设备的数据)持有。

本决策部分取代[点词释义浮卡](../feature/2026-09-20-word-definition-popover.md)的外观与高度选择，以及[词句合并](../simplification/2026-09-12-word-sentence-learning-merge.md)保留的发音获取路径；两篇笔记的内容协议、坐标边界和共享会话决策继续有效。[死 public API 清理](../simplification/2026-09-12-dead-public-api-sweep.md)中保留发音能力的理由仍成立，接口事实随本决策更新；服务变更同时遵循[隐私披露决策](../process/2026-09-09-scope-privacy-incident-docs.md)。

## Alternatives considered

继续查询词典条目再取音频：增加一次网络往返，并把等待分散到条目查询和音频下载；点词只需要发音，不需要这层词典正文。

让词卡高度随内容增长：短释义能少占空间，但逐条到达的内容会不断移动卡片边界，用户更难稳定滚动和切换标签。

在阅读器 Web 脚本中增加选区：能直接修改字词样式，但需要跨原生桥接同步关闭和清理；只传递词片段矩形就能表达当前词卡的短暂标记。

## Consequences

无缓存的单词发音依赖有道服务，失败时仍需要阿里云配置才能生成语音；直连音频沿用不按音色区分的缓存语义。词卡减少遮挡并保持位置稳定，长内容和大字号需要更多内部滚动。宿主使锚点失效时仍关闭整个词卡与标记。

## Testing

词卡定向测试覆盖固定高度、长内容滚动、非零 overlay 原点、跨行词分段标记、重复打开、外部点击、返回与程序关闭；触觉反馈和标记生命周期一并断言。网络测试覆盖直取字节、完整响应等待预算、无效响应、取消及 TTS 回退。桌面 widget 测试不能证明真机震感与原生视口的最终视觉效果。

Chromium 与 WebKit 的 126 项脚本回归覆盖软连字符跨行时的逐片段矩形，断言相邻单词不被标记。Android 与 Swift 原生矩形测试覆盖片段变换、裁剪、非法数据和旧载荷兼容；Android 词卡设备验收覆盖点词、渐进内容、外部关闭、旋转及请求释放，iOS 模拟器宿主编译通过。
