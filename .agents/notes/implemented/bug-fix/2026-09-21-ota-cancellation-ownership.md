# Agent Note: OTA 取消等待任务退出并保留终态

Status: implemented

## Problem

上游 `ota_update 7.1.0` 收到取消后立即确认，但旧任务仍可能写文件、校验摘要或启动安装器。重试复用同一文件与插件实例字段，旧回调可能关闭新事件流或清掉新请求。Flutter 在等待取消时丢弃终态；若事件流先结束、取消通道再失败，界面会恢复到没有订阅的下载状态，无法关闭或重试。

## Decision

保留插件的 Dart 接口与安装路径，在[本地分支](../../../../third_party/ota_update/UPSTREAM.md)修补 Android 任务所有权。取消立即标记任务并中断网络，回执等到文件流关闭、摘要校验退出后再完成。原生主线程串行决定取消或安装；安装尚未交接时取消阻止交接，已经启动的系统安装器由用户处理。

进度、结束和取消等待者归属同一任务；回调只有仍拥有活动任务时才能改状态。旧任务退出前拒绝新请求，退出后的迟到回调不影响重试。事件订阅或引擎拆除也取消所属任务，文件不在写入期间被新任务覆盖。

`UpdateCheck` 在等待取消时保存终态并保持弹窗锁定。取消失败时优先恢复已收到的终态；仍有活动订阅才恢复下载，缺少终态的流结束转为失败。取消成功采用已取消状态，但保留已经交给系统安装器的事实。

## Alternatives considered

**只在 Dart 丢弃迟到事件**：不能停止原生写文件或安装，也不能隔离共用字段的新旧请求。

**取消后延迟固定时间再重试**：等待时长不能证明写入和校验已经退出，慢设备仍会发生竞争。

**取消通道失败后一律恢复下载**：事件流可能已经结束，只能在仍有订阅且没有终态时恢复。

## Consequences

取消可能等待正在执行的 SHA-256 校验完成；主线程不阻塞，界面继续显示取消中。维护本地插件补丁需要在升级时重放并运行原生回归；CI 与发布门禁通过现有 Android 测试入口执行这些回归。残留 APK 仍由启动回收负责。

本决策部分取代[委托插件下载和安装](../architecture/2026-09-21-ota-update-installer.md)中的取消语义，其安装入口、摘要要求与回收策略保留。

## Testing

Robolectric 驱动真实插件的 OkHttp 回调，以闩锁控制写入与校验，覆盖回执等待、重复取消、排队安装、迟到回调、订阅拆除、HTTP 失败、摘要失败和重试。Flutter 用例交错事件流终态与取消通道成功或失败，验证等待期间锁定、完成后退出 busy 并能重试。系统安装器和厂商设备行为仍需设备验收。

Android API 35 模拟器安装重建的 debug APK 并启动到书架；版本清单重定向连接发生 TLS 握手失败，在线下载、取消与安装交接没有完成设备验收。
