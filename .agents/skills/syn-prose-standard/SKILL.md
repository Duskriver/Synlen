# Synlen 文字标准（契约保留式编辑）

> 先识别契约，再动手精简。本技能负责句子级判断；放置与结构见 `syn-doc-standards`；会话视角残留见 `syn-trim-cot-leakage`。

## 1. 什么必须保留（契约）

义务（必须 / 禁止）、不变量、前置 / 后置条件、兼容性承诺、并发与生命周期约束、失败后果。这些被删除或弱化即为缺陷。

## 2. 完整命题原则

编辑前拆解句子的事实条款：主体与动作、条件与时序、情态（必须 / 可以 / 绝不）、负面保证与例外、归属、失败后果。
**所有事实条款存活**时才可删冗余表述；任何条款会丢失 → 重写而非删除。

## 3. 不是单向删减

代码、类型、函数签名无法传达必要契约时**补写**文字（例：`ref.onDispose` 为何必须与资源创建成对出现的约束）。判断标准：读者能否只凭代码 + 该文字正确使用模块而不踩坑。

## 4. 按位置的必要覆盖

| 位置 | 保留 | 删除 |
|---|---|---|
| public API dartdoc | 用途、约束、错误模式（中文，规范 §8） | 实现复述 |
| 内部 `//` 注释 | 代码说不出的约束（为何这样写） | 控制流复述、显而易见的翻译 |
| 模块头注释 | 模块边界与职责一句 | 历史说明 |
| 测试注释 | 非显然的 setup 意图 | "测什么"的自述 |
| docs/、README | 承重规则 + 链接 | 故事、状态说明、重复 |
| Agent Notes | Problem / Risks 的证据 | 修饰 |
| l10n 文案 | 完整命题（含情态与例外） | 为短砍信息 |
| commit message | 为什么（规范 §9） | 改了什么的流水账 |

## 5. 排除

- 生成物（`*.g.dart`、`*.freezed.dart`、l10n 生成物）：先改源（注解 / ARB）再重新生成。
- `.agents/notes/archived/`（密封）、`CHANGELOG.md` 历史条目。

## 6. 流程

1. 确认范围（scope / 分支基点）；缺范围先界定并声明。
2. 全范围检查（搜索 + 通读），不只看最大文件。
3. 每个候选分类：保留 / 补充 / 精简 / 重构 / 搁置；**不为达成删减量制造编辑**。
4. 应用 → 涉及代码跑 `dart format` + `flutter analyze` → `git diff --check`。
5. 报告：范围、明确修改、有意保留的边界情况、搁置项。
