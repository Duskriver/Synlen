# Agent Note: 按风险选择流程并复用决策记录

Status: implemented

## Problem

文件数门槛会把测试、l10n 和生成物带来的局部改动升级为规格工作；每次都更新笔记容易积累只记录执行过程的文字。“路过即修”还可能让一次修复扩大为无关清理。跨 feature 摘要漏写 domain 值类型与组合面例外时，agent 无法仅靠指令确定合法依赖。

## Decision

流程按行为、契约与回退成本选择，已有请求或 issue 提供充分规格并授权实施时直接继续；只补缺失的决策。具体路由由[开发规范](../../../../docs/development.md#按风险选流程)持有。

非平凡改动仍需关联决策记录；已有笔记准确覆盖时引用，事实或适用范围变化时更新，新决策才新增。[Agent Note 契约](../../README.md#何时写一篇)持有记录条件。必要的测试与 CI 门禁保持原有要求。

重构只覆盖任务所需或明确指定的区域，无关发现单独报告。部分细化[增量重构决策](../architecture/2026-08-10-incremental-refactor-over-big-bang.md)的整理范围；其增量演进与先补测试的要求继续有效。

跨 feature 摘要与[现行允许形态](../../../../docs/architecture.md#跨-feature-依赖)一致，修正文档和技能的遗漏，不修改分层门禁或扩大依赖权限。

## Alternatives considered

**保留文件数门槛与每次更新笔记。** 放弃：文件数量不能代表兼容或行为风险；重复登记执行过程也不增加下一次决策所需的信息。

**完全取消规格与决策记录。** 放弃：新契约、迁移和不可逆操作仍需明确验收与约束，后续维护也需要知道方案为何成立。

**继续在触及的文件中顺手清理。** 放弃：同文件的无关问题仍会扩大回归面和评审范围；必要重构保留，其他问题单独报告。

## Consequences

局部改动可以直接进入实现与针对性验证；新决策仍有可追溯的理由。引用旧笔记前必须核对它是否仍准确，已有请求也不能替代其中尚未确定的验收标准或额外操作授权。

取代检查覆盖了[文档分层](2026-09-09-layered-docs-system.md)、[分层门禁](2026-09-09-layer-gates.md)、增量重构与[上游调研](../../proposed/process/2026-09-26-selective-lumina-upstream-adoption.md)。本决策落实调研中的流程建议；产品改进候选仍由原提案评估。旧笔记继续拥有各自决策，没有整篇取代或归档。
