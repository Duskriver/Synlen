# Agent Note: 重开 EPUB 复用校验结果并按需补充目录标题

Status: implemented

## Problem

EPUB 的净化结果虽然按内容摘要缓存，但每次打开仍先读取整包计算 SHA-256，重复打开的准备成本随媒体资源体积增加。Android 插件补充 Locator 的目录标题时，无目录项或单目录项也会启动 Content 迭代器；它解析整章正文，并可能为判断章节边界读取下一章，尽管这些场景不需要字符位置。

## Decision

`ReadiumEpubPublicationCache` 为应用私有源文件持久化路径索引，以大小、修改时间和状态变更时间验证已知摘要。匹配且校验标记或净化副本仍存在时直接复用；否则重新计算摘要并走原准备流程。索引以临时文件原子替换，净化规则版本同时作用于索引与内容缓存。

Android 的目录补充逻辑先按资源过滤目录项。没有匹配项时保留 Locator，只有一个匹配项时直接补充标题和目录链接；多个匹配项继续使用原选择器顺序。完整 Locator、已有目录链接和章节内多锚点的语义不变。

## Alternatives considered

**每次重开都重新读取整包计算摘要**：能检测全部内容变化，但导入后的应用私有文件不是编辑工作区。首次验证后继续为未变化的文件读取所有图片和字体，增加与当前可见页面无关的 I/O。

**仅按修改时间复用**：等长改写并恢复修改时间时可能命中旧结果，因此状态变更时间也参与失效；内容变更后的完整校验仍由原摘要与净化流程负责。

**所有目录都跳过正文选择器**：同一资源内存在多个目录锚点时仍需判断当前段落属于哪一项，只对无需消歧的情况短路。

## Consequences

首次打开、源文件变化和缓存清理后的准备仍执行既有长度、CRC 与活动内容检查。本优化减少重复准备和目录补充的工作，不承诺任意 EPUB 首次排版均在一秒内完成；当前章节的 WebView 排版仍由 Readium 负责。

文件索引只适用于应用私有目录中的藏书，不作为可被外部进程保留全部元数据后修改的文件校验方案。索引不是书库真源，损坏或删除后可以重建。

## Testing

内容缓存回归覆盖重建缓存实例、损坏索引、等长改写并恢复修改时间、净化副本被删除，以及既有 CRC、活动内容与字体字节保留检查。130 章、64 MiB 媒体的本地重复准备基准由 399–406 毫秒降至 0–1 毫秒；这是电脑上的文件准备阶段耗时，不是手机上完整打开的耗时。

目录补充的七项原生回归覆盖无目录、唯一目录、多目录、已有目录链接、无正文选择器及非 EPUB；无歧义场景以禁止调用正文 loader 断言，不依赖设备时钟阈值。Android 模拟器的真实 TXT/EPUB 阅读验收覆盖跨章、重排和重开后的完整位置恢复。

Android 17 真机以《The Complete Illustrated Sherlock Holmes》同一章节、同一进度重复打开，用正文截图与稳定页一致作为完成条件。旧版三次采样为 2.438、2.297、2.300 秒，新版预热后三次为 1.371、1.457、1.284 秒；这些值包含截屏开销，是该设备与藏书的采样上限，不代表所有图书或首次打开耗时。
