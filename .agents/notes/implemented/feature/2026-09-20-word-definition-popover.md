# Agent Note: 点词释义浮卡

Status: implemented

## Problem

点词学习需要保留原文位置，并先给出足够理解当前句子的简义。底部面板与连续 Markdown 正文把查词位置、核心释义和扩展解释分开，难以同时满足指向原词与渐进展示分区内容。

## Decision

词卡由 `LearningEntry` 持有弹出路由，阅读器只传入原词、句子上下文、全局逻辑坐标锚点和阅读主题。DOM 提供可见词矩形，WebView 边界负责坐标转换，词卡按可用空间避开目标词；宿主在页面、排版或视口改变时关闭词卡。该划分让坐标来源留在阅读器，浮层布局与学习会话留在 learning。

阅读器展示正文前等待预加载 WebView 启动完成，并在订阅转场动画时同步当前状态。这样既能处理订阅前已完成的转场，也能保证屏幕内容与取词桥接使用同一原生视口，避免预加载尚未完成时创建另一份空白视图。

视口变化按开卡时的尺寸、设备像素比、安全区和键盘边距快照判断。iOS 可在这些值不变时重复发送指标通知；把通知本身当作重排会使刚打开的词卡立即关闭。Web 渲染器在初始化时记录实际视口尺寸，使第一次横竖屏切换也触发正文重排。

单次 DeepSeek 请求按简义、解释、近义词、构词输出四条 NDJSON。仓储合并 SSE 分片并校验完整记录，controller 逐条发布结构化快照；空缺字段与空内容有不同含义，未到达的标签可以独立展示加载状态。句子仍使用 Markdown 和原有底部面板，词、句共享查询与音频生命周期的理由见[词/句学习 controller 与 repository 合并](../simplification/2026-09-12-word-sentence-learning-merge.md)。

只有完整且成功结束的词内容写缓存，中途失败保留已验证内容供阅读并提供重试。词、句 prompt 版本独立，使词内容格式变化只淘汰词文本缓存；现有文本列存储完整 NDJSON，无数据库表结构迁移。音标和发音指向原文词形，原形仅用于词条标题，避免朗读内容与读者选中的词不一致。

## Alternatives considered

继续用一段 Markdown 承载词内容：文本标题不足以可靠区分增量到达的分区，截断响应也难以判断哪些字段完整，因此词条使用固定顺序的结构化记录。

等待整份 JSON 到齐后展示：结构校验简单，但简义必须等待扩展解释生成完成，失去优先回答当前查词问题的机会。

让词、句共用一个 prompt 版本：实现简单，但词卡格式变化会使未变化的句子分析缓存失效。两个版本保留共同哈希算法和现有存储表。

## Consequences

结构化协议对模型输出更严格：缺字段、乱序或格式错误终止本次内容请求，已验证的分区仍可阅读；损坏缓存当作未命中重新请求。字段语义、入口和生命周期契约见 [learning 模块参考](../../../../docs/subsystems/learning.md)，坐标与宿主关闭条件见 [reader 模块参考](../../../../docs/subsystems/reader.md)。

浮卡受剩余屏幕空间限制，大字体或长内容需要内部滚动。收藏不属于本次词条能力。词侧内容分支独立后，共享 controller 继续承担音频与取消编排；这部分不取代词/句合并决策。
