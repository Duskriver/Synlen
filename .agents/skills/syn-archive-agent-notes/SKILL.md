# Agent Notes 生命周期

> 契约见 `.agents/notes/README.md`（先读它）。
> 核心：**缩减活跃决策语料而不抹除历史**——按语义价值判定每条笔记；字数和年龄只是发现线索，绝不是归档标准。

## 1. 新增时查取代

每条新笔记触发对同主题活跃笔记的审计：新笔记取代既有记录时，被取代者在**同一 PR** 归档，不得推迟。

## 2. 按未来价值分类

- **implemented**：理由 / 边界规则仍能约束未来变更 → 保留；决策彻底完成且无未来指导价值（一次性修复、微小调整、约束已固化进代码与规范）→ 归档。
- **proposed**：**永不归档**。不值得推进就如实改判 rejected 并写明理由。
- **rejected**：仅当失败提案仍是"诱人且有意义的错误"（防止重蹈覆辙）→ 保留作护栏；否则删除文件。

## 3. 归档操作

1. `implemented/` → `archived/`，仅在 `Status:` 行下插入 `Archived: YYYY-MM-DD`，**不改正文**。
2. 检查入站引用：`rg "notes/.*<slug>|<slug>" docs/ .agents/ lib/`，更新指向。
3. 归档即**密封**：此后永不编辑、移动、删除。

## 4. 验证与报告

- `git diff --check`；链接核对。
- 报告：保留 / 归档 / 删除的数量与理由，以及每个真正的边界案例。
