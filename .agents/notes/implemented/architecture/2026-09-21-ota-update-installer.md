# Agent Note: 委托 ota_update 下载和安装 APK

Status: implemented

## Problem

APK 下载、校验与原生安装横跨 Dart 和 Android 配置，自行拼装 URI 会让下载落点与安装入口脱节。[安装路径事故](../../archived/bug-fix/2026-09-20-update-install-uri-path-mismatch.md)说明单测覆盖网络和文件操作仍不足以证明系统安装器能读取文件。更新弹窗在下载期间关闭还会丢失后续安装动作。

## Decision

固定 `ota_update 7.1.0`，由插件下载、计算 SHA-256，并通过默认 Intent 方式打开系统安装器。`UpdateService` 保留清单读取与参数检查，插件工厂经 provider 注入；每次重试创建新实例，避免插件缓存已关闭的事件流。文件使用 `synlen-update.apk` 固定名称，由插件覆盖下载；FileProvider 仅暴露私有 `files/ota_update/` 目录。

`UpdateCheck` 订阅插件事件，处理进度、安装器启动、取消和失败，错误细节只入日志。`installerOpened` 不代表安装完成。下载期间不能重复检查或下载，也不能直接关闭弹窗；用户取消需等原生调用返回，Provider 释放时取消下载与订阅。

清单必须提供 HTTPS 直链和 64 位十六进制 SHA-256。插件原生实例收到 null 摘要时可能沿用上一次值，空字符串则会触发校验失败，因此不保留缺失摘要时放行的策略。现有 Gitee 发布脚本始终生成摘要；缺失或畸形摘要在调用插件前转为本地化错误，备用链接继续可用。插件不删除校验失败的文件，用例在报告摘要错误前清理它。

`ota_update 7.1.0` 的 Java 和 Dart 对 `INSTALLATION_ERROR` 与 `ALREADY_RUNNING_ERROR` 排序相反，两者统一归为安装失败，避免依赖错误的具体分类。Manifest 移除插件附带的系统安装权限与外部存储写权限。

### 安装包回收

插件不会自动回收成功安装或取消后的 APK。下载前将目标版本与 SHA-256 写入私有目录的 `pending.json.tmp`，刷新后原子替换 `pending.json`；写入失败不启动插件，准备期间取消也不继续下载。记录先于插件执行，避免覆盖安装结束进程后丢失目标信息。

Android 启动时先执行本地回收，再运行应用界面，避免清理与新下载竞争同一文件。当前版本达到目标时删除 APK，再删除记录；尚未达到目标时流式计算摘要，只删除不完整或损坏的包，完整待安装包继续保留。无记录或记录损坏时保守保留 APK；临时记录可删除。回收失败只记日志，保留记录供下次启动重试。

原生 `cancel()` 在发出 OkHttp 取消信号后立即返回，不等待写入回调退出；部分下载错误也可能早于文件写入结束。因此取消和普通失败只保留回收记录，到下次启动、旧进程下载已停止时清理。校验失败已经完成文件读取，可立即删除；清理异常不能覆盖摘要错误。拉起安装器时不删包，也不把切回前台视为安装完成。

## Alternatives considered

**继续维护 Dio 下载与手写安装 URI**：保留了最易脱节的跨语言契约，无法获得插件对安装入口的集中维护。

**改用 Google Play 的 in_app_update**：依赖 Google Play 分发，不符合公开 APK 直链渠道。

**使用插件可选的 PackageInstaller 模式**：它增加会话与广播接收器配置；当前只需系统确认安装，默认 Intent 路径足够，且不能把插件安装进度当成覆盖安装成功。

**取消返回或拉起安装器后立即删除 APK**：前者不能证明原生写入线程已停止，后者不能证明系统安装器已读完。延迟固定秒数仍不能证明这两个条件，因此回收使用启动时机和本地版本、摘要证据。

## Consequences

版本比较、Gitee 清单格式与更新弹窗保留；UI 不持有 APK 路径，不包含安装 Intent。取消下载后可重试；授权未知来源安装后重试会重新下载。插件取消针对网络请求，已经交给系统的安装界面由用户决定，不能由 Flutter 撤回。

本决策部分取代[更新检查移出 presentation](2026-09-09-update-flow-out-of-presentation.md)的安装分工，以及[下载加固](../bug-fix/2026-09-09-update-backup-hardening.md)的缺失摘要兼容策略；手写 URI 对齐方案归档，保留旧版用户需手动安装一次的事故记录。

## Testing

用例测试覆盖清单比较、下载参数、原生事件映射、校验失败清理、重复操作、失败重试、取消与 Provider 释放。Android 配置测试核对插件 Provider、目录暴露范围和权限；设备安装流程仍需原生验收，不能用 fake 事件推断安装成功。

回收测试使用临时目录模拟跨服务实例重启，覆盖本地版本比较、完整包保留、残留删除、缺失或损坏记录、清理错误重试，以及准备期间取消和记录写入失败。启动用例的成功结果表示文件操作已结束。

Android API 35 模拟器通过重建的 debug 应用验证启动入口：在私有目录放入 APK 与回收记录夹具，分别确认达到目标版本后删除、完整待安装包保留、不完整文件删除、记录损坏时保留文件并正常进入书架。夹具验收覆盖真实目录与启动编排，不代表再次完成宿主自身的覆盖安装；测试结束删除夹具。

Android API 35 模拟器验收：包含插件的 debug 宿主从 Gitee 下载真实 APK，完成 SHA-256 校验、未知来源授权、系统安装确认，将设备上的正式包从 `0.3.4+304` 覆盖为 `0.3.5+305`，安装后成功启动。宿主使用独立 debug 包名，因此该证据覆盖文件交接和系统安装，不等于验证更新宿主自身被替换时的进程生命周期；真机与厂商系统未验收。
