# Agent Note: 阅读拖动按落页位置完成，四周留白可打开菜单

Status: implemented

## Problem

Android 阅读器在单指拖过半页、停顿后松手时回到原页。同一资源内的快速横滑可以前进，末端停顿的输入连续两次保持原页。Readium 的落页判定把初末速度乘积不大于零视作取消，松手前停顿也被归入取消，没有按已经拖出的距离完成普通拖动。

菜单事件只来自正文 JavaScript。正文外的字号边距和底部进度区域属于 Flutter，缺少点击处理；因此段落间空白可以打开菜单，底部及其他页面留白却没有反应。

## Decision

保留 Readium 的排版、位置、滚动和动画实现，在 Android Navigator 的实际落页判定处补齐普通拖动。慢速拖动或末端停顿达到落页距离时完成相邻页导航；短移、取消、多指和正文内部横向滚动不应触发补翻。固定 SDK 来源并记录差异补丁，使修改与上游源码可核对。

`ReaderPageStage` 接收原生视口之外的留白短点，正文视口覆盖该命中层。只读观察整页指针用于取消跨区域多指序列，不参与原生手势竞争。正文内的词句、链接、图片与边缘翻页仍由已有桥接和 SDK 处理。菜单切换共用就绪、抽屉与学习浮层守卫。

## Alternatives considered

**只要求快速甩动**：不能满足常见的拖动、停顿、松手操作，也不能解决页面已经跟手移动后又回弹的问题。

**在 SDK 回弹后额外调用翻页**：同一次输入会同时启动 SDK 回弹和新的翻页动画，增加重复翻页及最终位置竞争，无法稳定定义一次拖动的完成时机。

**在正文上方铺整页点击层**：正文点词、图片和链接也会命中该层，菜单容易与学习、翻页同时触发。只接收原生视口之外的 Flutter 留白能保持事件归属。

## Consequences

Android Navigator 固定为 3.3.0 的本地源码模块，其余组件使用官方 Maven 包。运行逻辑只修改 `R2WebView` 的落页判断；源码、资源、补丁、来源摘要与组合许可见 [UPSTREAM](../../../../third_party/flutter_readium/android/readium-navigator/UPSTREAM.md)。升级 Readium 时需要重新核对该补丁与上游手势契约。

位移判定只补充原速度分支未落页的拖动，不改变 SDK 原有快速甩动分支。正文内部横滚需要外层页面移动或原生触边证据，不能仅凭手指位移推算翻页。菜单留白层只观察指针，不加入原生视口的手势竞争。

原生回归通过独立模块任务进入 PR 与发布门禁，复用 APK 同样必须通过；源码在检查期间变化则拒绝发布。构建诊断报告属于忽略的产物，不能导致干净工作树被误判。

## Testing

2026-09-20，在 Android 17 真机上用同一本 EPUB 复现：修复前两次拖过半页、停顿 400ms 后松手均停在原页，底部点按不能打开菜单。修复后连续 6 次双向停顿拖动和 4 次双向快慢横滑各移动一页；短拖、取消和纵向滑动均保持原页。章尾第 126 页停顿松手可进入下一资源第 1 页，反向停顿拖动回到原章末页。底部进度、左侧和右侧留白的菜单开关通过，测试后回到起始阅读页。

原生单测 59 项通过，其中 12 项重放真实 `R2WebView.onTouchEvent` 路径，原始停顿回弹用例先红后绿；47 项为上游测试。Robolectric 重放 Chromium 的外层滚动和触边结果，不替代复杂 EPUB 的实际布局验收。留白命中与页面守卫的 7 项 Flutter 测试、Chromium / WebKit 的 118 项回归、发布脚本的 25 项回归通过。

普通入口调试 APK 在真机覆盖安装并启动，8 个 arm64 原生库通过 16 KiB 对齐检查；原插件、SDK、PhotoView 与字体许可确认包含在 APK。此次设备验证覆盖 Android，不构成所有 EPUB 或 iOS 真机兼容性承诺。
