# ADR-0001: 采用增量重构，不做 big-bang 重构

2026-08-10 决定：项目恢复开发前，先建立开发规范（docs/DEVELOPMENT_STANDARDS.md），架构采用增量演进（strangler fig + Boy Scout Rule），**不做**一次性大规模重构。

## Status

accepted

## Considered Options

1. **先 big-bang 重构再开发**：全量统一分层后再加新功能。放弃——项目停更过一段时间、测试覆盖率接近零（6 个测试文件 / 180 个源文件），重构期间功能停滞且回归风险无法兜底；没有规范约束，重构完写新代码仍会漂移。
2. **先写规范，增量重构**（选定）：规范先行给新代码锚点；旧代码路过即修；只有成为新功能地基的区域才安排专项重构（且先补测试）。
3. **不重构、直接开发**：放弃——现状存在 7+ 处分层违规（presentation 直连 data）、reader 层逻辑集中在 UI、55 处 print，直接堆功能会加速腐化。

## Consequences

- 短期内代码库分层不一致（部分模块已规范、部分未修），可接受，靠 TECH_DEBT 清单追踪。
- 新功能开发必须遵守规范，开发速度初期略慢，后期因杠杆效应（深模块）收益。
- 专项重构前必须先补该区域测试，测试安全网是重构的前提条件。
